# 맞춤장사 OS 프로젝트 컨텍스트

> 새 채팅에서 이 파일을 먼저 읽는다. 전체 요구사항은 `prd.md`, 화면 참고는 `visual-references.md`, 구현 근거는 `docs/implementation-audit.md`를 확인한다.

## 1. 제품 정의

- 프로젝트명: 맞춤장사 OS
- 음식점 마케팅 대행사의 내부 운영 ERP이자 사장님용 운영 리포트 시스템
- 목적: 외식업 매장이 검색되고, 방문되고, 재방문되는 구조를 90일 안에 세팅하고 그 과정을 표준화한다.
- 핵심 사용자: 회사 관리자/대표, 매니저, 클라이언트 사장님, 매장 직원, 향후 방문 고객
- 핵심 원칙: 자동화보다 수동 입력과 검수형 흐름을 먼저 완성하고, 모든 성과와 업무를 매장별 히스토리로 남긴다.

## 2. 확정 MVP

### 매장과 대시보드

- 업체/매장 등록, 수정, 삭제, 엑셀 일괄 등록
- 관리 시작일은 월요일만 선택, 계약/관리 기간은 4주 단위 선택
- 담당자와 음식점 업종은 관리자 관리 목록에서 선택
- 네이버 플레이스 URL/MID, 광고 계정, 외부 계정, 내부 메모, 사장님 성향/핵심 니즈 저장
- 전체 운영 대시보드: 주차, 업체명, 담당자, 비즈머니, 네이버 유입, 매출, 업무현황, 바로가기
- 모든 주요 열은 오름차순/내림차순 화살표 정렬
- 주차 필터, 업체 검색, 담당자 필터, 비즈머니/유입/매출 하락 및 상승 정렬
- W0~W3 최근 4주 흐름 표시
- 상태 기준: 증가/유지 초록, 5% 이상 감소 주황, 10% 이상 감소 진한 빨강, 데이터 없음 회색

### 매장별 운영 화면

- 네이버 광고 상세
- 네이버 유입/키워드 분석
- 여신금융 매출
- 관리자 일일업무
- 일일업무
- 주간업무
- 사장님 보고서 미리보기 및 MID 기반 읽기 전용 공유 링크
- 매장 정보 및 MID 기반 정보안내문 링크
- 매장 주간 데이터 흐름
- 모든 화면은 선택한 업체 기준으로 동작하며 업체 미선택 시 데이터 없음으로 표시

### 플레이스 CSV 분석

- 네이버 플레이스 통계 CSV를 매장별, 월요일~일요일 주간 단위로 업로드
- 업로드한 기간만 저장하고 표시하며 없는 기간은 0이 아닌 `데이터 없음`
- 여러 주차 파일을 누적하고 유입수, 유입 키워드, 유입 채널, 기간별 증감 데이터를 계산
- 주간/월간 조회 및 기간 선택
- 통합 CSV 다운로드
- 대시보드와 매장 주간 데이터 흐름에서 DB 값을 조회

### 매출 데이터

- 여신금융협회 `.xls/.xlsx` 수동 업로드
- 날짜별, 시간대별, 요일별, 평일/주말 매출
- 매출 건수, 신규/재방문 추정, 재방문률, 평균 객단가
- 카드사와 마스킹 카드번호 기준의 추정값임을 표시
- 목표 개월 수, 목표 매출, 목표 재방문률, 목표 객단가, 테이블 수, 종합 CAC를 입력
- 현재 데이터에서 목표까지 월별 필요한 신규/재방문 고객을 선형 계획으로 계산하고 그래프 툴팁에 수량 표시

### 키워드 조합과 꿀키워드

- 1 지역/장소, 2 수식어, 3 메뉴, 4 특수, 5 단독, 6 목표 키워드 입력
- 조합 체크박스 선택 후 `선택 조합으로 생성`, `초기화`
- 기본 예시: `1/3`, `1/2/3`, `1/2/4`, `1/4`, `2/3`, `2/4`, `5/3`, `5/4`
- 중복 제거/공백 옵션
- 태그용: 50개씩 한 열 단위로 A, B, C...에 배치
- 파워링크용: 1000개씩 한 열 단위로 배치
- 태그/파워링크 CSV 다운로드
- 꿀키워드 탐색은 네이버 검색광고 API보다 `map.naver.com/p/search`의 페이지 수 확인이 우선
- 지도 페이지 수가 3 미만인 키워드만 유효 후보로 먼저 추리고, 그 후보에 한해 검색광고 API 검색량을 후처리
- 키워드 작업은 매장별 히스토리로 저장하고, 결과를 매장 정보의 키워드 목록에 반영
- 결과별 등록 여부를 체크할 수 있게 한다.
- 지도 페이지 수 수집은 브라우저 자동화 워커가 필요하며 Vercel 서버리스만으로 완료하지 않는다.

### 업무, 통화, 체크리스트

- 공용 일일업무 수집함: 업체 선택, 업무명 입력, 마감일 입력/수정, 업무명 수정
- 긴급 벨과 중요 별 토글로 긴급+중요/긴급/중요/일반 분류
- 기한 지남 진한 빨강, 오늘 주황, 미래 일반색
- 완료 업무는 일마감 히스토리에 기록
- 매장별 추가 업무와 소통 히스토리로 관리 미흡 매장 식별
- 관리자 일일업무: 요일별 고정 체크리스트와 매장 관리상태 요약
- 주간업무: 1~4주 업무 추가/삭제/수정, 상태, 마감, 증빙 이미지, 월별 히스토리 탭
- 매장 정보 안에 해당 매장의 주차별 업무 리스트와 수정 기능 표시
- 통화 요약 텍스트 업로드 → 매장 히스토리 저장 → 핵심 업무 후보 생성 → 선택한 후보만 업무 등록
- 추후 실제 통화 녹음 업로드/전사로 확장

### 세팅 체크와 정보안내문

- 매장 세팅 항목 추가/삭제/수정
- 기본 순서: 대문사진, 대문영상, 대표키워드, 상세설명, 찾아오는길 후킹, 쿠폰 후킹, 공지사항 후킹, 메뉴 상단 3개, 메뉴 SEO/AEO, 세트/미끼메뉴
- 진행률: 30% 미만 빨강, 30~60% 주황, 60~80% 노랑, 80~100% 초록
- 항목별 듀데이트와 완료 상태
- 네이버/당근/인스타/구글 광고 체크
- 전문사진촬영일, 먹플루언서 진행일을 달력과 히스토리로 누적
- 항목별 비포/변경 스크린샷 업로드
- 정보안내문은 전역 질문 템플릿을 관리자 수정, 매장별 답변을 업체와 연결
- 섹션 버튼으로 이동하고 완료 초록, 일부 작성 주황, 미작성 빨강
- 불필요한 사진 질문은 제거
- 사장님 공유 링크는 읽기 전용, 내부 정보와 비밀번호는 노출하지 않는다.

## 3. 현재 구현 상태

- UI 프로토타입은 `app/page.tsx`와 컴포넌트에 구현되어 있다.
- 주요 화면과 버튼 구조는 존재하지만 일부는 아직 localStorage 기반이며 실제 DB 연동 전이다.
- Supabase 프로젝트와 핵심 테이블/인덱스/RLS가 생성되었다.
- 생성 테이블: `erp_stores`, `erp_place_csv_uploads`, `erp_place_keyword_rows`, `erp_place_channel_rows`, `erp_sales_uploads`, `erp_keyword_jobs`, `erp_keyword_results`
- API: `GET/POST /api/erp/stores`, `POST /api/erp/place-uploads`
- 서버 전용 Supabase 클라이언트: `lib/supabase/admin.ts`
- `.env.example`에는 `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`만 기록하며 실제 키는 커밋하지 않는다.
- `npm run build` 통과 상태
- 검색광고 API 로컬 HTTP 연결은 확인했으나 운영 환경의 실제 키와 비즈머니 조회는 별도 검증 필요
- 네이버 지도 페이지 수는 서버 fetch 방식이 막힐 수 있어 Playwright/Chromium 워커가 필요
- 매출 파서는 현재 브라우저 중심 프로토타입이며 DB 저장 API가 다음 작업

## 4. 다음 개발 순서

1. Vercel 환경변수와 Supabase 연결 스모크 테스트
2. 매장 GET/POST를 DB에 연결하고 localStorage 매장 목록을 제거
3. 플레이스 CSV 파서/업로드/기간 조회/대시보드 연결
4. 여신금융 업로드 파서/중복 제거/신규·재방문/매출 그래프 연결
5. 키워드 조합 결과 저장과 50/1000 열 단위 CSV 다운로드 검증
6. 지도 페이지 수 브라우저 워커와 꿀키워드 작업 상태/히스토리 연결
7. 검색광고 API 검색량과 비즈머니를 지도 필터 결과 후처리로 연결
8. 주간업무/일일업무/관리자 체크리스트/통화 히스토리 DB 연결
9. 세팅 체크리스트, 증빙 이미지, 정보안내문 템플릿/답변 DB 연결
10. 사장님 읽기 전용 보고서, 인증/RBAC, 운영 보안 강화

## 5. 데이터 원칙

- 원본 업로드 파일과 정규화된 분석 행을 분리한다.
- 원본은 보존하고 분석 결과는 재계산 가능하게 한다.
- 매장 ID와 업로드 기간을 모든 분석 데이터의 필수 키로 사용한다.
- 중복 업로드는 파일 식별자/기간 또는 거래 식별키로 차단한다.
- 데이터가 없는 기간은 0으로 만들지 않는다.
- 대시보드는 localStorage가 아니라 Supabase 데이터를 기준으로 만든다.
- 민감 계정과 API Secret은 환경변수/암호화 저장을 사용하고 저장소에 넣지 않는다.
