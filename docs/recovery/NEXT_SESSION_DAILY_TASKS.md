# 다음 작업 인수인계 - 일일 업무 기입과 매니저 관리

기준 커밋: 이 문서와 함께 커밋되는 최신 `recovery/stage-1c-store-registry` 브랜치.

## 이번 반영

- 검색광고 비즈머니는 원 단위 정수만 표시한다. 음수 또는 소수 단위는 `0원` 처리한다.
- 비즈머니가 100,000원 이하이면 네이버 광고 화면과 운영 대시보드의 잔액 글씨를 빨간색으로 표시한다.
- 현재 배포 주소는 `https://mkt-erp.vercel.app` 이다.

## 다음 최우선 구현: 업무를 실제로 기입하는 흐름

목적은 기존 장사닥터의 `일일 업무` 화면처럼, **오늘 해야 할 업무만** 매니저별/매장별로 모아 실제 작업을 기록하고 사장님 보고서에 그대로 보여 주는 것이다.

### 확정된 업무 규칙

1. 수동 `완료` 버튼은 제거한다.
2. 매니저가 업무 상세에서 메모, 링크, 사진 중 하나라도 저장하면 상태는 자동으로 `기입완료`다.
3. 아무 기록이 없으면 상태는 `미기입`이며, 당일이 지나면 `업무 누락`으로 표시한다.
4. 사장님 보고서에는 `완료`라는 표현 대신 `기입완료`, `진행 예정`, `업무 누락`을 쓴다.
5. 사장님 보고서의 업무 행을 열면, 매니저가 입력한 글/링크/사진을 읽기 전용으로 펼쳐 본다.
6. 운영 대시보드의 주차별 진행 바는 기입완료 건수 ÷ 해당 주의 전체 업무 건수로 계산한다. 바를 누르면 그 매장의 일일 업무 화면으로 이동한다.
7. 매니저는 자기 담당 매장만 본다. 관리자는 전체 매장을 본다.

### 4주 계약 사이클 규칙

- 관리 시작일을 기준으로 28일짜리 1개 사이클(1~4주차)을 생성한다.
- 재계약이 확정되면 바로 다음 28일 사이클과 해당 업무 묶음을 생성한다.
- 계약 종료 뒤 재계약이 없으면 매장은 `일시정지`로 전환하며, 새 업무 묶음을 만들거나 오늘 업무에 노출하지 않는다.
- 이전 사이클의 업무·기입 내용·사장님 보고서는 삭제하지 않고 보존한다.

### 필요한 화면

- 좌측 `일일 업무`: 오늘 날짜 기본값, 담당자/매장 필터, 담당자 → 매장 → 오늘 업무 순으로 표시.
- 각 업무 행 클릭: 우측 상세 패널에 메모 입력, 링크 입력, 사진 여러 장 첨부, `기록 저장` 버튼.
- 매니저 홈: `오늘 미기입 매장`과 `오늘 미기입 업무` 요약.
- 공개 `/store/[uid]/report`: 주차별 업무 목록과 기록된 작업 증빙을 읽기 전용으로 표시.

### 관련 코드 위치

- `app/page.tsx`: 현재 내부 화면 라우팅, 대시보드 주차 바, 업무 화면 진입점.
- `components/daily-tasks/daily-tasks-page.tsx`: 일일 업무 목록 UI가 있으면 이 파일을 우선 사용.
- `components/public-store-work-list.tsx`: 사장님 공개 보고서의 업무 목록.
- `app/api/erp/stores/[storeId]/work-updates/route.ts`: 업무 기록 저장/조회 API.
- `components/stores/store-info-page.tsx`: 매장정보 저장과 템플릿/업무 생성 흐름.

### 반드시 확인할 데이터 보존 위험

매장 정보 저장 시 업무 동기화 로직이 기존 업무 기록을 전부 삭제하지 않도록 확인한다. 업무 템플릿을 수정해도 이미 입력된 메모·첨부파일은 보존되어야 한다.

## 그 다음 순서

1. 업로드 이력 다중 업로드, 삭제, 수정.
2. 사장님 보고서/정보안내문/매장정보 좌측 메뉴를 전체 공용 템플릿 편집으로 분리하고, 대시보드의 버튼만 매장별 링크로 유지.
3. 검색광고 자동 수집 시간을 11:00, 17:00 포함하도록 실제 스케줄러 구조를 정리.
4. 목표 키워드 순위 추적은 매장별 3개 키워드부터 하루 1회 기록하는 별도 단계로 구현.
