# 맞춤장사 OS 다음 작업 인수인계

최종 정리: 2026-07-20

## 지금 상태를 한 문장으로

매장 원장과 업로드 검수의 기반은 만들었지만, 현재 대시보드 화면에는 예전 샘플/임시 저장 화면이 남아 있어 실운영을 시작하기 전 정리 단계가 필요하다.

## 이미 확정한 운영 원칙

- 새 매장은 매장명만으로 먼저 등록할 수 있다. 매출, 네이버, 여신금융, 광고 데이터는 모두 나중에 연결하는 선택 항목이다.
- 기존 장사 ERP의 44개 과거 매출 파일은 검수 전용이다. 검수 결과는 아직 맞춤장사 OS 대시보드에 표시하거나 DB에 저장하지 않는다.
- 기존 ERP 매장명과 OS 매장은 이름만으로 자동 연결하지 않는다. `source_company_id`를 기준으로 관리자 확인 후 연결한다.
- 운영 데이터는 모두 하나의 `store_id`에 연결한다.
- 데이터 없음, 수집되지 않은 날짜, 실제 0원, 수집 오류를 서로 구분한다.
- 계정 비밀번호, Service Role Key, 광고 Secret Key, 여신금융 비밀번호를 코드/DB/localStorage/업로드 파일에 평문으로 저장하지 않는다.
- 고객/사장님에게 보이는 명칭은 `맞춤장사 OS`만 사용한다. `장사닥터`는 과거 데이터 원본 식별자와 기술 경로에서만 남길 수 있으며, 화면/공유 링크/문구에서는 모두 제거한다.

## 최근 완료

- 브랜치: `recovery/stage-1c-store-registry`
- 최신 커밋: `75f5525 feat: allow data-free store registration`
- 매장명만으로 매장 원장을 생성하는 서버 검증 추가
- 대시보드의 `업체 추가` 버튼이 빈 신규 매장 작성 화면을 열도록 수정
- 기존 샘플 계정/비밀번호/Secret Key 문구를 제거하고 브라우저 임시 프로필 저장을 중단
- 과거 매출 JSON/CSV 업로드는 선택 또는 드래그앤드롭 후 DB 변경 없는 검수만 수행
- 1년치 JSON 검증 결과: 44개 매장, 13,620일, 매출 24,247,436,540원, 결제 505,418건, 계약 검사 통과

## 다음 작은 작업 단위: 매장 원장 실사용화

### 목표

데이터가 없어도 매장을 먼저 만들고, 기본정보/특이사항/월별 세팅 상태를 각각 저장할 수 있게 한다.

### 구현 범위

1. `erp_stores`에 사장님 연락처와 사업자등록번호를 추가한다. 번호는 관리자만 볼 수 있게 마스킹/권한을 적용한다.
2. 사업자등록증 이미지는 비공개 Storage에 올리고, `store_id`로 연결한다.
3. 매장 기본정보와 특이사항을 분리 저장한다.
4. 월별 세팅 상태는 빈 상태에서 현재 관리월만 시작하고, `월 생성`/`월 삭제`/`항목 추가`/`항목 삭제`를 지원한다.
5. 모든 화면 표기와 공유 URL에서 장사닥터를 맞춤장사 OS로 교체한다.
6. 일일업무의 기본 요일을 실제 한국 날짜 기준으로 정한다.

### 제외

- 44개 과거 매출의 실제 DB 반영
- 네이버/여신금융 자동 수집
- 검색광고 쓰기 자동화
- 사장님 보고서 외부 공개 링크 발급

## 다음 작업 전에 필요한 설정

Vercel 프로젝트 `do-sun/naver-place-marketing-erp`의 Preview 환경에 다음 두 서버 환경변수를 등록해야 실제 DB 저장을 검증할 수 있다. 값은 채팅/커밋에 넣지 않는다.

- `SUPABASE_URL`
- `SUPABASE_SERVICE_ROLE_KEY`

## 검증 기준

- 매장명만 입력해도 신규 매장이 저장되고 목록에 즉시 나타난다.
- 매출/네이버/여신 데이터가 없어도 오류가 나지 않는다.
- 기본정보·특이사항·월별 세팅을 각각 저장 후 새로고침해도 유지된다.
- 사업자등록증은 관리자 권한 외에는 열리지 않는다.
- 화면과 공유 링크에 `장사닥터` 표기가 남지 않는다.
