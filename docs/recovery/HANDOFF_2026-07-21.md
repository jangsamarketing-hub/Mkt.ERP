## 이번에 추가된 기능

### 매장별 데이터 등록

매장 정보 화면에서 각 매장에 다음 파일을 올릴 수 있다.

- 여신금융 승인내역: `.xls`, `.xlsx`
- 네이버 플레이스 기존 파일: `.csv`
- 네이버 플레이스 신규 수집 파일: `.json`

신규 네이버 JSON은 기존 CSV 테이블에 억지로 합치지 않는다. 원본을 비공개 Storage에 보관하고, 기간·스키마·중복 여부를 `erp_naver_place_json_imports` 원장에 먼저 기록한다. 이후 `Raw → Snapshot → Fact → Analytics` 단계에서 사실 테이블과 대시보드로 연결한다.

### 매장 일괄 등록

대시보드의 업체 추가 영역에서 매장명만 여러 줄로 넣어 일괄 등록할 수 있다. 매출·네이버·여신금융 데이터가 아직 없어도 매장 등록은 가능하다.

## 원격 DB 적용 상태

다음 테이블은 원격 ERP Supabase에 적용되어 있다.

- `erp_naver_place_json_imports`

이 테이블은 직접 SQL 실행으로 적용했다. 저장소 migration 파일도 함께 존재하지만, Supabase migration 이력에는 별도로 기록되지 않았을 수 있으므로 다음 스키마 점검 때 이력과 실제 스키마를 비교한다.

## 배포 및 환경 설정 원칙

- 민감한 값은 Vercel의 Sensitive 환경변수로만 보관한다.
- 코드·문서·커밋에는 비밀번호, Service Role Key, 외부 계정 비밀값을 남기지 않는다.
- 환경변수 변경 후에는 새 Vercel 배포가 필요하다.
- 운영 로그인 검증은 성공했으며, 로그인 실패 시 가장 먼저 운영 주소의 최신 배포 여부를 확인한다.

## 다음 작업 권장 순서

다음에는 **매장 정보 화면의 실제 등록/저장 UX 보완**부터 진행한다.

1. 사장님 연락처, 사업자등록번호, 사업자등록증 이미지, 특이사항을 `store_id` 기준으로 저장
2. 각 구역별 저장 버튼 및 저장 결과 표시
3. 월별 세팅 항목을 현재 관리월부터 생성·삭제할 수 있게 변경
4. 이후 한 개의 테스트 매장을 기준으로 여신금융 파일과 네이버 JSON 업로드부터 실제 저장 검증

이 순서는 데이터가 없는 신규 매장도 바로 등록하고, 이후 필요한 데이터만 차례로 붙일 수 있게 하기 위한 것이다.
