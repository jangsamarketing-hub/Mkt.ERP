# 맞춤장사 OS 현재 작업 기준

마지막 정리: 2026-07-20

## 지금까지 확정한 원칙

- 모든 운영 데이터의 기준키는 맞춤장사 OS의 단일 `store_id`다.
- 화면 표기는 `장사 ERP`로 통일한다. 기존 원본과 DB 이력 호환을 위해 내부 기술 식별자 `jangsadoctor_erp`와 기존 테이블명은 당분간 유지한다.
- 여신금융 승인 상세 원본과 기존 ERP의 일별 매출 이력은 서로 다른 원장에 보관한다.
- 데이터 없음, 미제공 날짜, 실제 0원, 원본 오류를 섞지 않는다.
- 기존 ERP의 매장명만으로 맞춤장사 OS 매장을 자동 병합하지 않는다. `source_company_id` 연결을 관리자 확인 후에만 저장한다.
- 관리자 비밀번호나 외부 플랫폼 비밀번호는 코드·DB·업로드 파일에 평문으로 저장하지 않는다.

## 현재 구현 상태

- 기준 브랜치: `recovery/stage-1c-store-registry`
- 최신 커밋: `7fcc23b`
- 운영 기준 매장 원장과 Stage 2 수입 제어 테이블은 원격 ERP Supabase에 적용되어 있다.
- 과거 매출 이관 화면: `/admin/imports/jangsadoctor`
  - JSON 또는 CSV 선택·드래그앤드롭
  - 반영 전 검수만 수행, DB 저장은 아직 열지 않음
  - 대시보드의 `엑셀 업체등록`은 여신금융 XLS/XLSX 전용으로 유지
  - 대시보드의 `과거 매출 이관` 버튼은 위 검수 화면으로 연결

## 제공된 과거 매출 파일 검수 결과

### JSON 원본

- 파일: `jangsadoctor_sales_analytics_batch_v1.1.0_2025-07-01_2026-07-19.json`
- 44개 매장, 일별 매출 12,348행
- 매출 합계: 22,199,819,700원
- 결제 건수: 467,132건
- 실제 0원: 2일
- 미제공 날짜: 988일
- 데이터 형식 오류: 0건

### CSV 대조본

- 파일: `jangsadoctor_sales_analytics_batch_v1.1.0_2025-07-01_2026-07-19.csv`
- 정상 일별 매출: 12,348행 / 39개 매장
- 일별 매출 대상 외 행: 975행
- 원본 오류 행: 5행
- CSV는 검수용 변환본이며, JSON 원본을 이관 기준 파일로 우선 사용한다.

## 다음 작은 단계

1. JSON 검수 결과에서 44개 매장별 `source_company_id`와 맞춤장사 OS 매장을 연결하는 관리자 확인 화면을 만든다.
2. 연결이 승인된 매장만 일별 매출 원장에 저장한다.
3. 재업로드해도 같은 매장·같은 날짜는 중복 저장하지 않고, 변경된 값만 감사 로그와 함께 갱신한다.
4. 저장 전·후 합계, 미제공 날짜, 실제 0원, 제외 행 수를 다시 보여준다.

## 아직 하지 않는 것

- 매출 대시보드 디자인 변경
- 여신금융 원본과 과거 일매출 이력 병합
- 신규/재방문 고객 수 확정
- 외부 계정 자동 로그인 또는 자동 수집
- 검색광고 쓰기/자동 입찰
